🔥 CARACTERÍSTICAS NUEVAS
═════════════════════════

1. ENDPOINT: Obtener tareas por fecha de vencimiento
   ────────────────────────────────────────────────
   GET /api/tareas/ordenadas/vencimiento?limit=10
   
   ✨ Características:
   └─ O(log N) - Ultra rápido incluso con 100K tareas
   └─ Redis ZSET hace la ordenación automáticamente
   └─ Sin cargar todos los datos en Node.js
   └─ Parámetro limit opcional (default: 10)
   
   Caso de uso: "Próximas tareas a vencer"

2. ENDPOINT: Obtener tareas por prioridad
   ──────────────────────────────────────
   GET /api/tareas/ordenadas/prioridad?limit=10
   
   ✨ Características:
   └─ O(log N) - Ultrarrápido
   └─ Prioridad 5 (máxima) aparece primero
   └─ Scores negativos para orden correcto
   └─ Parámetro limit opcional (default: 10)
   
   Caso de uso: "Tareas más importantes"

3. ENDPOINT: Limpiar tareas vencidas
   ──────────────────────────────────
   DELETE /api/tareas/limpiar/vencidas
   
   ✨ Características:
   └─ Elimina automáticamente tareas pasadas
   └─ O(log N + M) - Muy eficiente
   └─ Usa ZREMRANGEBYSCORE para eliminar por rango
   └─ Retorna cantidad de tareas eliminadas
   
   Caso de uso: "Limpieza automática diaria"


🗄️ ESTRUCTURA DE DATOS REDIS
═════════════════════════════

ANTES (solo Hash):
┌─────────────────────────┐
│ Hash: tareas:{email}    │
│ ├─ id1 → {tarea_json}   │
│ ├─ id2 → {tarea_json}   │
│ └─ id3 → {tarea_json}   │
└─────────────────────────┘
Problema: Sin ordenación automática

AHORA (Hash + 2 Sorted Sets):
┌─────────────────────────────────────────────┐
│ Hash: tareas:{email}                        │
│ ├─ id1 → {tarea_json}                       │
│ ├─ id2 → {tarea_json}                       │
│ └─ id3 → {tarea_json}                       │
│                                             │
│ ZSET: tareas:{email}:by_due_date            │
│ ├─ 1705000000 : id1  ← próxima a vencer    │
│ ├─ 1705100000 : id2                         │
│ └─ 1705200000 : id3  ← más lejana           │
│                                             │
│ ZSET: tareas:{email}:by_priority            │
│ ├─ -5 : id1  ← máxima prioridad             │
│ ├─ -3 : id2                                 │
│ └─ -1 : id3  ← prioridad baja               │
└─────────────────────────────────────────────┘
Ventaja: Ordenación automática O(log N)

🎓 CONCEPTO CLAVE: Sorted Sets
═══════════════════════════════

Un Sorted Set es como un Set normal pero con un score:

Set normal:
[id1, id2, id3, id4, id5]
└─ No hay orden garantizado

Sorted Set:
[
  {score: 1705000000, value: id1},  ← Mejor puntuación / fecha más próxima
  {score: 1705100000, value: id2},
  {score: 1705200000, value: id3},
  {score: 1705300000, value: id4},
  {score: 1705400000, value: id5}   ← Peor puntuación / fecha más lejana
]
└─ Siempre ordenado por score

Ventaja: ZRANGE te da los primeros N elementos sin ordenar en app


💡 TIPS DE USO
══════════════

✅ Siempre usa limit en endpoints de ordenación
   └─ GET /api/tareas/ordenadas/vencimiento?limit=10

✅ Ejecuta limpiar vencidas periódicamente
   └─ Automáticamente con cron job o task scheduler

✅ Verifica datos en Redis CLI
   └─ $ redis-cli
   └─ > ZRANGE tareas:email:by_due_date 0 -1 WITHSCORES

✅ Usa parámetros de límite para evitar sobrecargar
   └─ Default: 10, máximo recomendado: 100

✅ Mantén sincronizado Hash + ZSET
   └─ Cuando actualices, actualiza ambos
