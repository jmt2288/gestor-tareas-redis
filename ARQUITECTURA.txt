│  ┌────────────────────────────────────────────────────────────────┐│
│  │ MIDDLEWARE                                                     ││
│  │ ├─ express.json()   - Parsear JSON                            ││
│  │ ├─ cors()           - Control de origen                       ││

│  │ RUTAS Y HANDLERS                                               ││
│  │                                                                ││
│  │ Autenticación:                                                ││
│  │ ├─ POST /api/auth/registro      → bcrypt hash + Redis Hash   ││
│  │ └─ POST /api/auth/login         → JWT token                  ││
│  │                                                                ││
│  │ Tareas Básico:                                                ││
│  │ ├─ GET /api/tareas              → HGETALL + Parse            ││
│  │ ├─ POST /api/tareas             → HSET + ZADD (2 ZSET)      ││
│  │ ├─ PUT /api/tareas/:id          → HSET + ZADD update         ││
│  │ └─ DELETE /api/tareas/:id       → HDEL + ZREM (2 ZSET)      ││
│  │                                                                ││
│  │ Tareas Avanzado (Sorted Sets):                                ││
│  │ ├─ GET /ordenadas/vencimiento   → ZRANGE O(log N)           ││
│  │ ├─ GET /ordenadas/prioridad     → ZRANGE O(log N)           ││
│  │ └─ DELETE /limpiar/vencidas     → ZREMRANGEBYSCORE          ││
│  └────────────────────────────────────────────────────────────────┘│
└──────────────────────────┬──────────────────────────────────────────┘
                           │
                    Redis Protocol
                           │

│  │ │     }                                                         ││
│  │ └─ Field: user2@example.com                                    ││

│  │ │       "fechaCreacion": "2024-01-08T..."                      ││
│  │ │     }                                                         ││
│  │ ├─ Field: 1700234567890                                        ││
│  │ │  └─ Value: {...}                                             ││
│  │ └─ Field: 1700345678901                                        ││
│  │    └─ Value: {...}                                             ││
│  └────────────────────────────────────────────────────────────────┘│

│  │ Key: tareas:user1@example.com:by_due_date                      ││

FLUJO DE DATOS: Crear Nueva Tarea
══════════════════════════════════

Usuario           Express              Redis
  │                  │                    │
  │─ POST /tareas ──▶│                    │
  │  {titulo,        │                    │
  │   prioridad: 5}  │                    │
  │                  │  Validar token     │
  │                  │  Crear tarea       │
  │                  │  (ID = Date.now()) │
  │                  │                    │
  │                  │─ HSET tareas:email ──▶ Hash
  │                  │  ID: {tarea_json}     (id, titulo, etc)
  │                  │
  │                  │─ ZADD by_due_date ──▶ ZSET
  │                  │  score: timestamp     (ordenado por fecha)
  │                  │  value: task_id
  │                  │
  │                  │─ ZADD by_priority ──▶ ZSET
  │                  │  score: -5            (ordenado por prioridad)
  │                  │  value: task_id
  │                  │
  │  ◀─ JSON ────────│
  │ {mensaje,       │
  │  tarea}         │
  │                 │

  │                  │
  │  ◀─ JSON array ──│
  │ [{tarea1},       │
  │  {tarea2},       │
  │  ...             │
  │  {tarea10}]      │

  │                  │

  │  actualizada}   │


FLUJO DE DATOS: Limpiar Vencidas

Usuario           Express              Redis

  │  limpiar/       │                    │
  │  vencidas       │                    │
  │                  │  Validar token     │
  │                  │                    │
  │                  │─ ZRANGEBYSCORE ──▶ ZSET
  │                  │  -inf, ahora         Obtiene vencidas
  │                  │ ◀─ [ids_vencidas]─│

  │                  │  id1, id2, ...        Elimina del Hash
  │                  │
  │                  │─ ZREMRANGEBYSCORE ──▶ ZSET
  │                  │  -inf, ahora          Limpia by_due_date
  │                  │
  │                  │─ ZREM by_priority ──▶ ZSET
  │                  │  id1, id2, ...        Limpia by_priority
  │                  │
  │  ◀─ JSON ────────│
  │ {tareasEliminadas│
  │  count}          │


COMPARACIÓN: Sin vs Con Sorted Sets
════════════════════════════════════

┌──────────────────────────────────────────────────────────────────┐
│ Escenario: Obtener Top 10 tareas por fecha (total: 1000)        │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│ ❌ SIN SORTED SETS (método tradicional):                         │
│                                                                  │
│   Node.js                    Redis                              │
│     │                           │                                 │
│     │─ HGETALL tareas:email ──▶ │                                 │
│     │ ◀─ [1000 objetos JSON] ──│                                 │
│     │                                                            │
│     │ (en Node.js)                                              │
│     │ 1. Cargar 1000 objetos en memoria                         │
│     │ 2. Parsear JSON 1000 veces                                │
│     │ 3. Sort por fecha: O(n log n) = 1000 * 10 = 10,000 ops  │
│     │ 4. Slice primeros 10                                      │
│     │ 5. Serializar 10 objetos a JSON                           │
│     │                                                            │
│     │─ JSON array ──▶                                           │
│                                                                  │
│   Operaciones: ~10,000 CPU operations + 1000 objetos            │
│                                                                  │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│ ✅ CON SORTED SETS (Redis hace el ordenamiento):                 │
│                                                                  │
│   Node.js                    Redis                              │
│     │                           │                                 │
│     │─ ZRANGE by_date 0 9 ──▶ │                                │
│     │ ◀─ [10 task IDs] ──────│                                │
│     │                        Tree Search: O(log 1000) = ~10 ops│
│     │ (en Node.js)                                              │
│     │ 1. Obtuve 10 IDs                                          │
│     │ 2. HGET × 10 para obtener detalles                        │
│     │ 3. Serializar 10 objetos a JSON                           │
│     │                                                            │
│     │─ JSON array ──▶                                           │
│                                                                  │
│   Operaciones: ~20 Redis commands + 10 objetos                  │
│                                                                  │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│ 🎯 RESULTADO:                                                   │
│                                                                  │
│   Reducción de operaciones: 10,000 / 20 = 500x más rápido      │
│   Reducción de datos: 1000 / 10 = 100x menos transferencia    │
│   Reducción de memoria en Node.js: 1000 / 10 = 10x menos       │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘

ESCALABILIDAD
═════════════

Crecimiento de datos: 1 usuario → 1,000,000 usuarios

┌─────────────┬────────────────┬────────────────┬──────────────┐
│ Usuarios    │ Tareas/Usuario │ Total Tareas   │ Rendimiento  │
├─────────────┼────────────────┼────────────────┼──────────────┤
│ 1           │ 100            │ 100            │ O(log 100)   │
│ 100         │ 100            │ 10,000         │ O(log 100)   │
│ 10,000      │ 100            │ 1,000,000      │ O(log 100)   │
│ 1,000,000   │ 100            │ 100,000,000    │ O(log 100)   │
└─────────────┴────────────────┴────────────────┴──────────────┘

✅ El rendimiento es INDEPENDIENTE del total de datos
✅ Cada usuario tiene su propio ZSET (particionado)
✅ O(log N) donde N = tareas de 1 usuario (100-1000)
✅ NO es O(log total de tareas)

Escalabilidad vertical:
├─ 1 servidor Redis → ~100K usuarios
├─ Redis Cluster → ~1M usuarios
└─ Sharding por email → ~10M usuarios
