✅ FUNCIONALIDADES IMPLEMENTADAS:

1️⃣  AUTENTICACIÓN CON JWT
    ├─ POST /api/auth/registro
    ├─ POST /api/auth/login
    ├─ Middleware de verificación de token
    ├─ Contraseñas hasheadas con bcrypt
    └─ Tokens JWT con expiración de 24h

2️⃣  CRUD DE TAREAS BÁSICO
    ├─ GET /api/tareas (obtener todas)
    ├─ POST /api/tareas (crear)
    ├─ PUT /api/tareas/:id (actualizar)
    └─ DELETE /api/tareas/:id (eliminar)

3️⃣  SORTED SETS AVANZADO ⚡
    ├─ GET /api/tareas/ordenadas/vencimiento?limit=N
    │   └─ Ordena por fecha vencimiento (O(log N))
    │   └─ Sin ordenación en Node.js
    │   └─ Usa Redis ZSET: tareas:{email}:by_due_date
    │
    ├─ GET /api/tareas/ordenadas/prioridad?limit=N
    │   └─ Ordena por prioridad (O(log N))
    │   └─ Scores negativos para orden correcto
    │   └─ Usa Redis ZSET: tareas:{email}:by_priority
    │
    └─ DELETE /api/tareas/limpiar/vencidas
        └─ Elimina tareas vencidas automáticamente
        └─ Usa ZREMRANGEBYSCORE (O(log N + M))

4️⃣  ESTRUCTURA DE DATOS REDIS
    ├─ Hash: usuarios
    │   └─ Field: email → Value: {usuario_json}
    │
    ├─ Hash: tareas:{email}
    │   └─ Field: task_id → Value: {tarea_json}
    │
    ├─ ZSET: tareas:{email}:by_due_date
    │   └─ Score: timestamp de vencimiento
    │   └─ Value: task_id
    │   └─ Ordenado por fecha ascendente
    │
    └─ ZSET: tareas:{email}:by_priority
        └─ Score: -prioridad (1-5)
        └─ Value: task_id
        └─ Ordenado por prioridad descendente

🎓 CONCEPTOS CLAVE DE SORTED SETS
═════════════════════════════════════

1. ZSET (Sorted Set) = Set + Score
   └─ Cada elemento tiene un score numérico
   └─ Automáticamente ordenado por score
   └─ Operaciones en O(log N)

2. Score = Criterio de Ordenación
   ├─ Por fecha: score = timestamp (1000 ms desde epoch)
   ├─ Por prioridad: score = -prioridad (negativo para invertir orden)
   └─ Por puntuación: score = puntos del usuario

3. ZADD (agregar/actualizar)
   └─ Comando: ZADD key score member
   └─ Si el member ya existe, actualiza el score
   └─ Complejidad: O(log N)

4. ZRANGE (obtener elementos)
   └─ Comando: ZRANGE key 0 -1
   └─ Retorna elementos ordenados por score
   └─ ZRANGE key 0 9 → primeros 10 elementos
   └─ Complejidad: O(log N + count)

5. ZREMRANGEBYSCORE (eliminar por rango)
   └─ Comando: ZREMRANGEBYSCORE key min max
   └─ Elimina todos los elementos con score entre min y max
   └─ Útil para limpiar datos vencidos
   └─ Complejidad: O(log N + M) donde M es cantidad eliminada

🚀 CÓMO EMPEZAR
═══════════════

1. Asegurate de tener Redis corriendo:
   $ redis-cli ping
   > PONG

2. Configurar variables de entorno:
   $ cp .env.example .env

🔧 COMANDOS REDIS ÚTILES
═════════════════════════

# Conectar a Redis
$ redis-cli

# Ver estructura de datos
> KEYS *
> HGETALL usuarios
> HGETALL tareas:usuario@example.com
> ZRANGE tareas:usuario@example.com:by_due_date 0 -1 WITHSCORES
> ZRANGE tareas:usuario@example.com:by_priority 0 -1 WITHSCORES

# Ver cardinalidad
> HLEN tareas:usuario@example.com
> ZCARD tareas:usuario@example.com:by_due_date

# Limpiar datos de prueba
> DEL usuarios
> DEL tareas:usuario@example.com
> DEL tareas:usuario@example.com:by_due_date
> DEL tareas:usuario@example.com:by_priority
